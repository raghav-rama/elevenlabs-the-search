# Running reference review

Source: [downloaded video](../../../references/Slow%20motion%20running%20-%20side%20view%20%28focus%20on%20legs%29.mp4), supplied by the user from [EMU Running Science Laboratory on YouTube](https://www.youtube.com/watch?v=p7sKgRAkVmw).

The 32.032-second file exports at approximately 29.97 fps. Its page describes capture at 100 fps, but capture/export rates alone do not establish the slowdown: the upload may repeat frames or contain additional timing changes.

The [opening samples](opening-steps.png) show successive alternating landings roughly 2.6 seconds apart. Matching the requested three alternating contacts per second suggests a reference-only playback multiplier around 7.8 (approximately 8x). This is an estimate to meet the creative cadence, not a verified restoration of original real time. Count contacts again after any approved preparation.

Useful features: continuous running already underway, side-on view, both feet visible through most of the cycle, and relatively consistent framing. The [overview](overview.png) samples the longer clip.

Transfer limitations:

- Runner faces left; Riley's legs shot moves right. A prepared reference would need a horizontal flip.
- Colored biomechanical overlays and a vertical stand overlap the performer. They can contaminate appearance transfer or obscure pose extraction.
- Treadmill running supplies gait but not the desired station/camera translation.
- Athletic shoes and high heel recovery differ from Riley's block heels and restricted skirt.
- Head is cropped out; this does not match Kling Motion Control's documented visible-head guidance.

Assessment: useful gait-analysis material and a possible prepared H3 motion reference, but unsuitable as a direct slow-motion input for the desired cadence. No reference speed change, flip, cleanup, generated-take modification, or model submission was performed. The user's rejection of speeding up generated takes remains in force; reference preparation is a separate proposal.

Metadata, source hash, and measurement limits are in [review.json](review.json).
